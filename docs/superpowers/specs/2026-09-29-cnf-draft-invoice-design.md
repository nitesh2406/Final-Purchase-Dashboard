# CNF Draft Invoice — Design

Date: 2026-09-29
Status: Approved section-by-section by user; pending review of this document

Extends the CNF Agent tab (`2026-09-28-cnf-unified-tab-design.md`). Today the
Batches sub-tab shows an *expected CNF charge* (estimate only) and a
"CNF invoiced" column comparing the goods part of CNF's invoices with the
goods value paid. There is no way to work out, and keep, what CNF's whole
invoice for a batch should come to.

## Decisions (user, 2026-09-29)

| # | Decision |
|---|---|
| 1 | "Generate Draft Invoice" produces a **saved draft** per batch. Its figures stay fixed until the user regenerates it. |
| 2 | **GST = IGST % (Settings) × (goods value + CNF charge).** |
| 3 | The CNF charge comes from a **category chosen in a dropdown** of the Settings rate categories (Sea: % of goods; Air: ₹ per kg). Choosing one pre-fills its rate, which the user can edit before the charge is computed. |
| 4 | "CNF Invoiced" compares CNF invoice **totals** with the draft's expected total. A CNF invoice covering several batches is shared **pro rata by its goods lines**. |
| 5 | Drafts live in a **new sheet** `CNF_Draft_Invoices`. |

## Behaviour

**Eligible row.** A batch (Sea or Air) whose status is `Delivered` and whose
shipments are all CNF-eligible (vendor invoice fully paid) — the same test the
backend applies on save, and on live data exactly the Delivered + `Paid`
batches — shows **Generate Draft Invoice**; once a draft exists
the button reads **Regenerate**, and saving replaces the draft.

**Draft form** (modal) for batch B:
- **Goods value** (read-only) = Σ `paidInr` of B's shipments from
  `get_cnf_shipment_values` (INR actually paid to the vendors).
- **Category**: dropdown of Sea categories (`CNF_Commission_Rates`: label,
  `ratePct`) for a sea batch, Air categories (`CNF_Air_Rate_Categories`:
  label, `ratePerKg`) for an air batch. Pre-selected: the batch carrier's
  shipment-partner default, else the only category for the mode if exactly
  one exists (same rule as `computeExpectedCnfCharge`); otherwise none (user
  picks).
- **Rate**: pre-filled from the chosen category; editable (> 0).
- **Weight (kg)**, Air only: pre-filled from the batch `total_weight_kg`;
  editable; required (> 0).
- **CNF charge** = Sea: rate × goods ÷ 100; Air: rate × weight.
- **IGST %** (read-only) = Settings value (`getIgstPercent_`, defaults to 5
  when never set).
- **GST** = IGST % × (goods + charge) ÷ 100.
- **Expected total** = goods + charge + GST.
- All money rounded to 2 dp at each step: charge, GST, total.
- **Save draft** / **Cancel**. With no category for the mode: "Add a Sea/Air
  rate category in Settings first", Save disabled.

**CNF Invoiced column**
- With a draft: `₹<invoiced total> of ₹<expected total>`, plus a small line
  `goods ₹… · charge ₹… · GST ₹… · draft by <email>, <date>`.
- Without a draft: today's `₹<goods invoiced> of ₹<goods value>` marked
  "goods only", and the button when eligible.
- *Invoiced total* of a batch = Σ over its shipments of `invoicedTotalInr`
  (below). Pending and approved CNF invoices count; rejected ones don't.

## Data model

New sheet `CNF_Draft_Invoices`, created (header row only) on the first save:

`Batch ID | Batch Type | Goods Value | Category ID | Category Label | Rate |
Weight Kg | CNF Charge | IGST Pct | GST | Expected Total | Shipments |
Generated By | Generated At`

- One row per batch; saving again overwrites that row.
- `Shipments`: JSON `[{ shipmentId, paidInr }]` the draft was built from.
- `Weight Kg` blank for sea. `Generated At` ISO timestamp.

## Backend (`gas_clone/cnf_unified.js`, routed in `doPost`)

| Action | Behaviour |
|---|---|
| `get_cnf_draft_invoices` | Read. `{ drafts: [...] }`, one per row, numbers as numbers, `shipments` parsed. Missing sheet = no drafts. |
| `save_cnf_draft_invoice` | Write, via `callGasAuthed` (`Generated By` = proxy-stamped `user_email`; refused without it). Input `{ batchId, categoryId, rate, weightKg? }`. Under the script lock: recompute goods from `getCnfShipmentValues_()` and refuse unless the batch exists, is `Delivered`, has ≥ 1 RMB-vendor shipment and **every** one is eligible (fully paid); category must exist for the batch's mode; rate > 0; air needs weight > 0. Recompute charge, IGST %, GST, total (never trust client numbers); upsert the row. Returns the saved draft. |
| `get_cnf_shipment_values` | Each shipment gains `invoicedTotalInr`: for every Pending/Approved CNF invoice, each line gets `invoice.total × line.amount ÷ Σ line amounts` (lines are always > 0; an invoice whose lines sum to 0 adds nothing). Existing `invoicedInr` / `remainingInr` / eligibility unchanged, so Log CNF Invoice is unaffected. |

`get_cnf_draft_invoices` is added to the frontend's cacheable reads; the
save clears the read cache like every write.

## Frontend

- `components/logistics/cnf/draftInvoice.ts`: `computeDraftInvoice({ mode,
  goods, rate, weightKg, igstPct })` → `{ charge, gst, total }` (the same
  rule as the backend, for the live preview).
- `components/logistics/cnf/CnfDraftInvoiceModal.tsx`: the form above.
- `CnfBatchesView.tsx`: also loads `get_cnf_draft_invoices` and the IGST %;
  button + new column content; reloads after a save.
- `services/cnfService.ts`: `fetchCnfDraftInvoices`, `saveCnfDraftInvoice`.
- `types.ts`: `CnfDraftInvoice`; `CnfShipmentValue.invoicedTotalInr`.

## Error handling

- Server refusals are shown inside the modal; the modal stays open.
- A failed load shows the existing retry banner, never an empty table.
- The server is the source of truth for every figure; the form's numbers are
  a preview.

## Testing

- Backend (CNF harness): sea and air arithmetic; IGST default 5; refusals
  (not delivered, part-paid shipment, unknown category, rate ≤ 0, air without
  weight, no identity); regenerate replaces the row; `invoicedTotalInr`: one
  batch counts in full, a two-batch invoice splits by lines, rejected counts
  0.
- Frontend: `computeDraftInvoice` unit checks with the same numbers.
- `npm run lint` at its 2 known errors; `npm run build` clean.
- After deploy (read-only): `get_cnf_draft_invoices` and
  `get_cnf_shipment_values` return the new fields; the user generates one
  draft and checks the figures.

## Related change shipped alongside

Each CNF sub-view keeps its last loaded data for the browser session
(`viewCache.ts`), so returning to the CNF tab from another page shows it
immediately and reloads in the background.
